## 0. 环境冒烟测试 (Smoke Test)

> 🛑 **Gatekeeper**: 测试开始前，必须通过以下 4 项检查。任何一项失败，直接打回开发构建，不进入功能测试。

* **SMOKE_01: 构建依赖检查 (NPM)**
* **操作**: 检查微信开发者工具文件树。
* **预期**: 必须存在 `miniprogram/miniprogram_npm/@vant/weapp` 目录。
* **失败后果**: UI 组件全崩，页面样式丢失。


* **SMOKE_02: 云环境初始化 (Cloud Init)**
* **操作**: 打开调试器 (vConsole)，查看 App Launch 日志。
* **预期**: 控制台无红色报错，且能看到 `wx.cloud.init` 成功调用的日志，`env` 参数必须指向当前测试环境 ID（非生产环境）。
* **失败后果**: 无法登录，无法存图。


* **SMOKE_03: 全局样式配置 (Force Light Mode)**
* **操作**: 切换手机系统至“深色模式 (Dark Mode)”，重新进入小程序。
* **预期**: 小程序背景仍强制保持**奶油白 (`#FFFBF5`)**，未随系统变黑。导航栏文字保持黑色。
* **失败后果**: 视觉崩坏，文字不可读。


* **SMOKE_04: Vant 组件按需引入检查 (Bundle Optimization)**
* **操作**:
1. 打开全局配置文件 `miniprogram/app.json`。
2. 检查 `usingComponents` 字段。
3. 随后打开任意页面配置文件（如 `pages/index/index.json`）对比。


* **预期**:
1. **全局干净**: `app.json` 的 `usingComponents` 中 **严禁出现** 任何 `van-` 开头的组件（如 `van-button`）。此处应为空，或仅包含极个别全站通用的自定义组件。
2. **局部引用**: Vant 组件必须且只能出现在具体 Page 的 `.json` 文件中。


* **失败后果**: 主包体积超过 2MB 限制，无法上传代码进行预览/发布。

## 1. 核心交互测试 (Interaction & Gameplay)

### 模块：水平磁吸刻度尺 (Magnetic Ruler)

> **关注点**: 物理手感、无数字设计、计分准确性。

* **CASE_101: 刻度尺滑动与磁吸物理反馈**
* **步骤**:
1. 在答题页，左右拖动刻度尺滑块。
2. 将滑块拖动到两个刻度点中间（悬空位置）并松手。


* **预期**:
1. 滑动经过刻度时触发 `uni.vibrateShort (light)` 震动反馈。
2. 松手后，滑块**自动吸附**（弹回）到最近的刻度点（实心点或空心圆），严禁停留在刻度之间。
3. 界面上**不显示**任何具体分数（如 +3, -3）。




* **CASE_102: 点击点选交互**
* **步骤**: 直接点击刻度尺最右侧的“大实心点”。
* **预期**: 滑块平滑移动至该点击位置，并触发吸附震动。


* **CASE_103: 计分逻辑映射验证**
* **步骤**:
1. 选中最左侧大点（Index 0）。
2. 选中中间空心圆（Index 3）。
3. 选中最右侧大点（Index 6）。


* **预期**: 对应后台（调试器 AppData 或 Logs）记录的分数应分别为 **-3分、0分、+3分**。



### 模块：防抖与流程控制

> **关注点**: 节流 (Throttling)、动画互斥。

* **CASE_104: 快速点击“确定”防御 (Debounce)**
* **步骤**: 在选中答案后，以 1秒 5次 的频率疯狂点击“下一题”按钮。
* **预期**:
1. 题目只切换一次（进入下一题）。
2. 不会出现连续跳过题目或进度条异常增加的情况。
3. 按钮在动画播放期间应处于 `Disabled` 态（视觉上虽无灰置，但逻辑不可点）。




* **CASE_105: 顶部通知条 (Top Notification)**
* **步骤**: 答题直到触发阶段转换（如 Q10 -> Q11）。
* **预期**:
1. 顶部下滑出通知条：“🎉 解锁青年阶段”。
2. **严禁**出现微信原生的黑色 `Toast` ("Loading" 或 纯文字框)。

## 2. 结果与授权测试 (Result & Auth)

### 模块：隐私与头像持久化 (Critical Red Lines)

> **关注点**: 微信合规、文件存储生命周期。

* **CASE_201: 隐私协议触发**
* **步骤**:
1. 清除本地缓存（模拟新用户）。
2. 完成 60 题，点击“生成人生档案”。


* **预期**:
1. 弹出微信官方底部的隐私授权弹窗。
2. 只有点击“同意”后，才弹出选择头像昵称的窗口。
3. 若点击“拒绝”，停留在当前页，无法生成海报。




* **CASE_202: 头像转存持久化 (核心 Bug 防御)**
* **步骤**:
1. 在授权弹窗中选择“微信头像”或“相册图片”。
2. 点击确定生成海报。
3. **查看 Network 请求**。


* **预期**:
1. 必须看到一个 `wx.cloud.uploadFile` 的请求（将临时路径转存为云端永久路径）。
2. 数据库 `users` 集合中，该用户的 `avatar_file_id` 字段必须是以 `cloud://` 开头的字符串。
3. **错误特征**: 若存储的是 `http://tmp/` 或 `wxfile://`，判定为 **Critical Fail**（会导致次日头像失效）。

## 3. 海报合成与容错 (Canvas & Robustness)

### 模块：竞态容错绘制

> **关注点**: 弱网环境下的 Plan B。

* **CASE_301: 海报生成 - 正常网络 (Plan A)**
* **步骤**: 在 4G/5G/WiFi 正常环境下生成海报。
* **预期**:
1. 4秒内完成绘制。
2. 海报背景为高清插画 (对应 MBTI 结果)。
3. 头像、昵称、小程序码清晰可见。




* **CASE_302: 海报生成 - 弱网超时 (Plan B)**
* **步骤**:
1. 开发者工具 -> Network -> 模拟 `Slow 3G` 或 `Offline` (模拟超时)。
2. 点击生成海报。


* **预期**:
1. 约 4-5 秒后，并未白屏卡死。
2. 自动降级生成一张“纯色背景 + 大字文案 + 小程序码”的简易海报。
3. 提示用户“网络繁忙，已生成极速版海报”。




* **CASE_303: 安全区域 (Safe Area) 适配**
* **步骤**: 使用 iPhone X / 13 / 15 Pro Max (带刘海屏机型) 模拟器。
* **预期**:
1. 结果页海报顶部文案未被“刘海”遮挡。
2. 底部按钮未被 Home Indicator (黑横条) 遮挡（应留白 68px）。

## 4. 社交裂变测试 (Social Fission)

### 模块：URL Payload 状态传输

> **关注点**: 闭环逻辑、参数解析。

* **CASE_401: 访客模式 (Guest Mode) 渲染**
* **步骤**:
1. 构造带参数的 URL 进入小程序: `/pages/index?mode=guest&mbti=ENFP&nick=TestUser`。
2. 观察首页渲染。


* **预期**:
1. 首页背景变为 ENFP 对应的结果底图（而非默认问号）。
2. 标题显示: “@TestUser 的真实人生居然是...”。
3. 底部按钮文案变为 **“我也要重启人生”**。




* **CASE_402: 访客转化闭环**
* **步骤**: 在访客模式下，点击“我也要重启人生”。
* **预期**:
1. URL 参数被清除。
2. 页面重载，恢复为默认“冷启动”状态（神秘人身份）。
3. 开始按钮恢复为“开始测试”。




* **CASE_403: 乱码/错误参数防御**
* **步骤**: 构造损坏的 URL: `/pages/index?mode=guest&nick=%E4%` (故意造成 URI Decode 报错)。
* **预期**:
1. 小程序**不白屏**，不报错崩溃。
2. 自动捕获错误，强制重定向到正常的首页（默认模式）。

## 5. UI/UX 细节专项

* **CASE_501: Android 伪磨砂兼容性**
* **步骤**: 使用 Android 真机（最好是中低端机型）打开。
* **预期**:
1. 按钮和卡片背景为半透明乳白色。
2. **不能**出现灰色不透明色块（这是使用了 CSS `backdrop-filter` 在旧版安卓内核上的典型 Bug，应确保已使用 `rgba` 替代方案）。




* **CASE_502: 字体排版舒适度**
* **步骤**: 检查长题目（3行文字）。
* **预期**:
1. 文本容器居中，但**内部文字左对齐** (Left Align)。
2. 行高 (Line-height) 明显，无拥挤感（符合 1.8倍行距要求）。
